- 版本: v1.0
- 日期: 2026-08-02
- 状态: 待评审（评审通过后进入实现）
- 方法论: SDD（Spec-Driven Development）+ TDD（Test-Driven Development）

---

## 1. 产品概述

**目标**：一个纯前端（静态文件即可部署）的 PWA 应用，一个搜索框，极速查询全日本所有铁路车站。

**核心功能**：
1. 输入实时给出候选车站，按「同口径使用人数」倒序排列。
2. 显示车站名、位置（精确到市町村）、接入线路（带准确颜色；计价线路名/运行系统名均可）。
3. 输入支持日文/英文；汉字支持简体、繁体、和制汉字；假名与罗马音可互换；长音符号（ō 等）可省略输入。

**非目标**（本次不做）：
- 时刻表、票价、换乘路径规划
- 车站编辑/评论/账号体系
- 地图渲染（只提供地图链接跳转）
- 后端服务、数据库（保持纯静态可离线运行）

## 2. 数据规格

### 2.1 数据源（已全部实测验证，2026-08-02）

| 源 | 用途 | 关键事实 |

| takumif/railway_colors_japan | 线路颜色 | 595 条（JR 计価线全覆盖且与官方一致：山手線#9acd32/東北線#00b2e5/中央線#f15a22/大阪環状線#e80000…） |

| OSM（已缓存 /tmp/osm_stations.json，9,090 element） | 站名读音 | name:ja-Hira + name:ja_rm（罗马音）+ operator + wikidata |
| pykakasi（已安装验证） | 读音补全 | 新宿→しんじゅく/shinjuku（hepburn）；专有名词需例外词典 |

| Wikipedia「大都市近郊区間 (JR)」wikitext | 验证用近郊区分类 | 5 个区域逐线路列出范围（东京/大阪/福冈/新潟/仙台） |

### 2.2 主数据模型（输出 app/data/stations.json）

每站一条记录（以 ekidata station_g_cd 组码为主键，站×线路合并为组）：

```
{
  id: "1130207",            // ekidata 组码
  name: "代々木",            // 汉字名（ekidata 原样）
  kana: "よよぎ",            // 平假名（Wikidata/OSM/pykakasi 合并）
  roma: "yoyogi",           // 罗马音（无长音符号、无空格，hepburn）
  pref: "東京都",            // 都道府県（pref.csv）
  muni: "渋谷区",            // 市区町村（地址解析，见 2.4）
  ward: "",                 // 政令指定都市的区（可选）
  lat: 35.68306, lon: 139.70204,
  lines: [ {name:"JR山手線", color:"#9acd32"}, ... ],   // 线路名+颜色
  rid: { v: 123456, y: 2019 },   // 排序用使用人数+年份（见 2.3）
  per: [ {op:"東日本旅客鉄道", line:"山手線", v:..., y:..., note:"..."} ], // 分运营商明细（详情页展示）
}
```

线路颜色表独立存 `data/lines.json`（线路名→颜色去重）。

### 2.3 使用人数（排序口径）— 已实测校验

- 来源：S12-25「乗降客数（人/日）」。同一数据集、同一字段 = 同口径。
- 已知值校验通过：JR東日本新宿 2024=1,333,618 ✓、東急渋谷 2024=1,770,430 ✓、JR西日本大阪 2024=751,006 ✓（均与官方公表一致）。
- **年份选择规则**：每站取 2015-2019 窗口内**最新可用年份**（优先 2019，依次回退 2018…2015）；`dataEorN` 标记无数据的年份跳过。
- **运营商合并规则**：S12 官方明示不同运营商数值「不得合计」（换乘重复计数的口径问题），故每站排序值 = 各运营商中 2015-2019 窗口内的**最大值**（绝大多数站只有一个运营商，天然一致）。详情页展示分运营商明细。
- 无数据站（约 17%）：排序置于全部有数据站之后，仍可搜索。
- **诚实披露**：S12 官方注明数值来源于各事业者公表、非统一方法计算（如 JR 系为乗車人員×2 的推定乗降）。这是日本唯一全国覆盖的官方年度车站客流系列，且本应用只用单一系列做排序，口径一致性优于任何混合方案。
- 归属规则：S12 的 `duplicate=1` feature 为实际值承载者（新宿 JR 的实际值挂在「中央線」feature 上而非「山手線」，实测确认）；`duplicate=2/3` 为 0 占位，丢弃。

### 2.4 市町村解析

- ekidata address 100% 有值（10,464/10,464），正则解析率 100%（唯一市町村 1,288 个）。
- 规则：`^(.+?[都道府県])?(.+?[市区町村])`；政令指定都市取「市」+ 后随「区」（京都市下京区→京都市/下京区）；郡部保留完整（亀田郡七飯町→七飯町，郡名入 ward 旁注）。
- 特别区（東京都 23 区）即市町村本身。

### 2.5 站名读音（kana/romaji）合并

1. Wikidata P1814 kana + OSM name:ja-Hira 优先（按站名+坐标匹配，名称去重后覆盖率约 90%）。
2. 剩余用 pykakasi 生成 + 例外词典修正（鹿児島→かごしま 等已知错误）。
3. romaji 一律 pykakasi hepburn 输出后处理：去长音符号（Tōkyō→tokyo）、去空格（Shin-Koyasu→shin-koyasu）。
4. 目标：kana/roma 覆盖率 ≥99%，不足 1% 的空白站不阻塞发布（搜索降级为其余字段）。

### 2.6 线路颜色

1. takumif CSV 为主（按运营商+线路名匹配，含 JR 计価线全部官方色）。
2. ekidata line_color_c 补缺（48 条，多为私铁）。
3. 手写补充表：运行系统色（埼京線#00ac9a、湘南新宿ライン#e6a817 等约 15 条，实现时以维基百科各线路条目 infobox 色为准核对）、东京地铁编号线名→通用线名映射（3号線銀座線→銀座線 #ff9500 等）。
4. 无官方色的线路：不显示色块，显示灰色中性标记（不编造颜色）。

### 2.7 线路名显示

- 直接用 ekidata 线路名（含运行系统：埼京線/湘南新宿ライン/上野東京ライン/宇都宮線 与 计价线 JR東海道本線(東京～熱海) 等并存，符合「按计价线路名 运行系统名统计皆可」）。
- 同一 station_g_cd 组内的多条线路合并去重。

### 2.8 大都市近郊区間分类（仅验证用）

- 解析 Wikipedia「大都市近郊区間 (JR)」wikitext：5 区域 × 逐线路（本线名 + 起讫站或「全線」）+ 府县全站规则 + 除外站。
- 线路站序由 ekidata join.csv（相邻站对）构建图得到。
- 判定：站在任一区域范围内 → 属于大都市近郊区間。
- 该分类**不进前端数据**，仅用于验证抽样。

## 3. 搜索规格

### 3.1 输入归一化（查询与索引两侧同一函数）

1. NFKC（全角→半角、ｶﾀｶﾅ→カタカナ）
2. 小写化（罗马音部分）
3. 假名统一：片假名→平假名（しんじゅく = シンジュク）
4. 长音剥离：ō/ū/ā/ē/ī → o/u/a/e/i（tōkyō→tokyo）
5. 空格/中黑点剥离（shin koyasu→shinkoyasu；代々木 无影响）
6. 汉字规范化：opencc s2t（简→繁）→ JP 新字体表（繁/旧字体→新字体，渋/澁/涩→渋、橋/桥→橋、沢/澤/泽→沢…表在构建期由站名字符集生成 + 人工核对）；ケ→ヶ
7. 索引键 = 归一化后的站名汉字 + 假名 + 罗马音（每个站 3-5 个键，含简/繁/新字体变体键）

### 3.2 匹配与排序

- 前缀匹配（候选 = 键以查询串开头的站），二分查找定位 + 顺序扫描，10,464 站全量毫秒级。
- 去重（多键命中同一站只计一次）。
- 排序：`rid.v` 倒序（无数据站恒排后）；同年份值相等时按 kana 字典序稳定排序。
- 结果上限 50 条（详情可滚动加载）。
- 空查询：显示空态引导文案，不输出列表。

### 3.3 查询示例（验收用例）

| 输入 | 应命中 |
|---|---|
| 新宿 / 新宿駅 | 新宿 |
| 涩谷 / 澁谷（简/旧体） | 渋谷 |
| しんじゅく / シンジュク | 新宿 |
| shinjuku / Shinjuku / SHINJUKU | 新宿 |
| tokyo / tōkyō / toukyou（假名直译兜底不做，仅长音剥离） | 東京 |
| 市ヶ谷 / 市ケ谷 | 市ヶ谷 |

## 4. UI/UX 规格

### 4.1 布局

- 单页应用。顶部标题栏（应用名 + 一句副标题 + 关于/数据源入口），中部大搜索框，下方候选列表，点击展开站详情（卡片式，可滚动）。
- 移动优先（iPhone 为主目标），桌面端自适应。
- 候选行：站名（大字）+ kana（小字灰）+ 市区町村 + 线路色块 chips（行首）+ 右侧使用人数徽标（"12.3万人/日" 简写，详情页给全量）。

### 4.2 详情页内容

- 站名（大）+ kana/romaji + 都道府県・市区町村
- 线路列表：色块 + 线路名（多线全列）
- 使用人数：主值（最大值运营商）+ 年份 + 分运营商明细表（运营商/线路/人数/年份/注记）
- 数据缺失站：显示「乗降データなし」（不显示编造的 0）
- 操作链接：Wikipedia(ja)、Google Maps、OpenStreetMap

### 4.3 文案与反 AI-slop 清单

- UI 语言：日语（面向日本铁路数据用户）；仅「データ出典」等元信息中日对照。
- 禁止：表情符号堆砌、渐变彩虹、拟人化欢迎语、加载动画废话、错误提示卖萌、"Powered by AI" 类标语。
- 空态文案示例：「駅名・かな・ローマ字で検索」（+ 示例搜索 chips）。
- 加载：数据加载中仅显示细进度条，无文案。
- 错误态（数据加载失败）：「データの読み込みに失敗しました。再読み込みしてください。」+ 重试按钮，无其他废话。
- 页脚：数据出典（国土数値情報 駅別乗降客数データ、駅データ.jp 系 ekidata、OpenStreetMap/Wikidata 读音）、更新日期、版本号。

### 4.4 主题与可访问性

- 浅色为主，`prefers-color-scheme: dark` 自动深色。
- 系统字体栈（-apple-system / Hiragino / Noto Sans JP / Yu Gothic）。
- 色块文字对比度：按亮度自动黑/白字。
- ARIA combobox 模式（输入框 + listbox + 键盘 ↑↓/Enter/Esc），焦点可见。

## 5. PWA 规格

- manifest.json：name「駅さがし」、short_name、theme/background color、icons（192/512 + maskable，SVG 源 + PNG 生成）。
- Service Worker：预缓存 app shell + stations.json，cache-first；网络失败离线可用。
- 图标：自绘车站符号（简洁几何形，非 AI 生成风格）。
- 部署：纯静态目录，任意静态托管可跑；最终部署到用户 VPS（tencent1，CF tunnel 后）需用户确认。

## 6. 验证规格（对应需求 verification）

### 6.1 抽样

- 用 2.8 分类器把全站分为「大都市近郊区間内/外」。
- 各区域真随机取 20 站（`secrets.randbits` 种子，种子与样本清单写入报告，可复现）。
- 排除：无维基条目的站（极小概率）、名称歧义站（同名多站）。

### 6.2 准确性对照（对 40 站逐一）

对照 Wikipedia 日语版（API 取 wikitext）：
1. 站名一致（含重定向解析）
2. 市町村一致（infobox 所在地 → 市町村提取）
3. 接入线路一致（infobox 所属路線/接続路線 vs 本应用线路集）
4. 有官方色的线路颜色一致（infobox 色 / 路线图色表抽查）
5. 使用人数量级 sanity check：维基 利用状況 vs S12，JR 系允许 ≈2 倍关系（乗車 vs 乗降），容差 ±30%

### 6.3 可找到性（对 40 站逐一）

对每站测试以下输入格式 × 前缀长度矩阵，断言「站出现在结果前 10 名」：
- 格式：汉字（原形/简体变体/繁体变体）、假名（平/片）、罗马音（带/不带长音）
- 长度：1/2/3/4 前缀（罗马音为 1/2/3/4 字母前缀）
- 全矩阵自动化（pytest），输出通过/失败明细。

### 6.4 报告

- `docs/verification-report.md`：抽样清单（含种子）、每站明细、失败项与根因、覆盖率统计。
- 失败项须在交付前修复或文档化说明原因（如维基缺数据）。

## 9. 风险与边界（诚实声明）

1. S12 客流为各社公表值的官方统合，非统一计算方法（见 2.3 披露）；JR 系为乗車人員×2 推定乗降。
2. 约 17% 车站无客流数据（官方未公表），排在有数据站之后。
3. ekidata 快照为 2022-09，其后新开/改名/废站不覆盖（如 2023+ 新站）。
4. 近郊区間分类依据维基条目（2026-03 更新版），仅用于验证抽样，非官方判定。
5. 读音来源为 人工例外 > OSM > Wikidata > Wikipedia首句注音，个别专有名词可能读错（例外词典持续修正）。残 212 站（2.2%）无读音：Wikipedia 消歧义页（金山等部分已手动补）或条目缺失，按原则留空不猜。
6. 站数口径：station.csv 10,464 行运行中记录按「组码×站名」合并为 8,974 独立站（同站多线路合并为新宿 1 站等）；SPEC 初版 ≥10,000 按原始行数制定，口径有误，已修正为合并后口径。
